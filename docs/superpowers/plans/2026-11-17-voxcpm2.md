# VoxCPM2 and GPU Memory on the Models Screen: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add VoxCPM2 as a fourth component with a free-text Style setting with suggestions. Show each model's GPU
memory on the Models screen before install. Export sessions whose lines have different sample rates.

**Architecture:**
- The Models screen gets `vram_gb` from `_component_view`.
- Setting specs gain a `"type": "text"` kind:
  - validated and cleaned in `models.clean_settings`;
  - rendered by `settings.js` next to the sliders.
- Export converts every selected take to the session's highest sample rate.
- VoxCPM2 is a new `MODELS["voxcpm"]` entry with its own venv worker (`workers/voxcpm/worker.py`), modelled on
  OmniVoice. Task 0, a spike the user runs on Windows, pins its version and values first.

**Tech Stack:** Python 3.11 stdlib HTTP server, NumPy, soundfile, vanilla JS UI, uv-managed venvs, `voxcpm` (pinned
by the spike), pytest, node --test.

**Spec:** `docs/superpowers/specs/2026-11-17-voxcpm2-design.md`

## Global Constraints

- All code, UI text and repo docs are in English. Non-ASCII characters are written as `\u` escapes in code and tests.
- Tests run without a GPU or network, using stub workers and stub packages under `tests/stubs/`.
- The worker blocks the network before importing libraries. Generation needs nothing from the network: load with
  `load_denoiser=False`, generate with `denoise=False`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Push with
  `timeout 120 git -c push.negotiate=true push`, directly on main.
- Style text: at most 200 characters. Parentheses are removed and whitespace is collapsed. It is sent as
  `f"({style}){text}"`, or as `text` alone when the style is empty.
- Settings stored before this change, which are all numbers, keep working unchanged.
- A session whose takes all share one sample rate exports byte-for-byte as before.
- Suites to run:
  - `python3 -m pytest tests -q`
  - `node --test "app/ui/tests/*.test.mjs"`
  - The Turkish-character grep prints nothing:
    `grep -rnP '[\x{00C7}\x{00E7}\x{011E}\x{011F}\x{0130}\x{0131}\x{00D6}\x{00F6}\x{015E}\x{015F}\x{00DC}\x{00FC}]' app workers tests scripts README.md SPEC.md`

## Review Focus

1. A line override equal to the session's style (including both empty) is not stored. The line then shows "Same as
   session" and no change count. Owner: Task 2,
   `test_line_text_override_equal_to_session_is_not_stored`.
2. A style made only of parentheses or spaces, e.g. `" ( ) "`, cleans to `""` and sends no prefix. Owner: Task 2,
   `test_text_setting_is_cleaned`; Task 4, `test_empty_style_sends_plain_text`.
3. In an export where line 1 is 24 kHz and line 2 is 48 kHz, pauses are counted at the output rate, not at the first
   line's rate. Owner: Task 3, `test_export_joins_mixed_sample_rates_at_the_highest`.
4. A string sent for a slider setting, e.g. `{"exaggeration": "a"}`, gives a 400 with a message, not a 500. Owner:
   Task 2, `test_slider_rejects_a_string`.
5. A tool (Whisper) has no `vram_gb`. Its row says "runs on the processor", never "~null GB". Owner: Task 1,
   `test_components_show_gpu_memory`, plus the UI check.

### Task 2: Text settings and the Style control

**Files:**
- Modify: `app/models.py` (`clean_settings` new; `validate_settings` uses it)
- Modify: `app/server.py` (`set_line_settings` stores the cleaned overrides)
- Modify: `app/ui/settings.js` (`sliders` renders text specs too)

- Modify: `app/ui/styles.css` (text setting and suggestion buttons)
- Test: `tests/test_sessions.py` (or `tests/test_server.py`, next to the existing settings tests)

**Interfaces:**
- Produces: `models.clean_settings(name: str, settings: dict) -> dict`. It validates and cleans the given keys
  only, adds no defaults, and raises ValueError with a message.
- `validate_settings(name, settings)` becomes `{**default_settings(name), **clean_settings(name, settings)}`.
- A text spec looks like this:
  `{"key", "type": "text", "label", "default": "", "max_length": 200, "help", "placeholder", "suggestions": [{"label", "value"}]}`.

- [ ] **Step 1: Write the failing tests**

  The tests add a text spec to a copy of `MODELS["chatterbox"]["settings"]` with monkeypatch:
  `{"key": "style", "type": "text", "label": "Style", "default": "", "max_length": 200, ...}`.

  - `test_text_setting_is_cleaned`:
    - `clean_settings("chatterbox", {"style": "  happy (very)\n warm "}) == {"style": "happy very warm"}`;
    - `{"style": " ( ) "}` cleans to `{"style": ""}`.
  - `test_text_setting_too_long`: 201 characters raises ValueError matching `"200"`.
  - `test_text_setting_must_be_text`: `{"style": 3}` raises ValueError.
  - `test_slider_rejects_a_string`: `PUT /api/sessions/<sid>/settings/chatterbox` with `{"exaggeration": "a"}`
    returns 400, with a message naming "Expressiveness".
  - `test_line_settings_store_cleaned_text`: `PUT .../lines/<lid>/settings/chatterbox` with
    `{"style": "(sad)"}`. The session JSON then has `line.settings.chatterbox == {"style": "sad"}`.
  - `test_line_text_override_equal_to_session_is_not_stored`: the session style is `"sad"`. A line PUT with
    `{"style": "sad"}`, after cleaning, stores no `chatterbox` entry on the line. The server drops overrides equal to
    the session-level value, after cleaning, so `"(sad)"` and `"sad"` are the same.

- [ ] **Step 2: Run them and see them fail**

  Run: `python3 -m pytest tests -q -k "text_setting or slider_rejects or cleaned_text or equal_to_session"`

- [ ] **Step 3: Implement `clean_settings` and use it**

**Interfaces:**
- Produces: `workspace._resample(samples: np.ndarray, src: int, dst: int) -> np.ndarray`. It takes int16 and returns
  int16 of length `round(len(samples) * dst / src)`, using linear interpolation (`np.interp`).

- [ ] **Step 1: Write the failing tests**

  - `test_resample_doubles_length`: `_resample(np.array([0, 100, 200], "<i2"), 24000, 48000)` has length 6, dtype

  - `test_export_joins_mixed_sample_rates_at_the_highest`:
    - Line 1 is a 24000 Hz take of 1.0 s, line 2 a 48000 Hz take of 1.0 s, each with `pause_after` 0.5.
    - The WAV export has frame rate 48000 and `48000 * (1 + 0.5 + 1 + 0.5)` frames.

- [ ] **Step 2: Run them and see them fail**

  Run: `python3 -m pytest tests/test_takes_export.py -q`
  Expected: FAIL. `_resample` is missing, and the export raises the "different sample rate" error.

- [ ] **Step 3: Implement**
